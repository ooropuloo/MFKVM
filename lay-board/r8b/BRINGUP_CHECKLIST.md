## 0. 開始前要備齊

- [ ] U1：Waveshare ESP32-P4-Module 基本款，SKU 28101，模組上的 R99 還在
- [ ] Type-C 電源，能供 1.5 A 以上。有可調電源更好（第 2 步用）
- [ ] 能傳資料的 USB-C 線，接 J5 到電腦
- [ ] USB 轉 UART 線，3.3 V 準位
- [ ] 三用電表、放大鏡或顯微鏡、細烙鐵頭、助焊劑
- [ ] U.FL 轉 SMA 線和 2.4 GHz 天線（第 7 步測 Wi-Fi 前要接上）
- [ ] 電腦上的 esptool（ESP-IDF 環境裡的 `python -m esptool`，或 `pip install esptool`）
- [ ] 韌體映像：照 `firmware/BUILD_v2.md` 編出 rev 3.x 和 pre-3.0 兩個映像（repo 裡不放編好的檔）

## 1. 開箱目視（不通電）

- [ ] 板子外形 40 × 40 mm，絲印是 **R8B**
- [ ] 板邊沒有凸出的郵票孔殘料（外殼牆離板邊只有 0.25 mm）；有的話磨平
- [ ] **U16（eFuse，背面）第 1 腳方向**：底視圖在左下角，靠 C71／R71／R72。對照 `fab_r8b\CPL_pin1_check.md`。**方向錯就不能通電**，會讓 VBUS 短到 GND
- [ ] 其他有方向的零件對照 `fab_r8b\CPL_polarity_pin1_r8.md` 看一遍
- [ ] U7（TC358743，背面 BGA）沒有歪斜；板廠有附 X-ray 圖的話看一下有沒有短路或空焊
- [ ] J2（HDMI）、J3、J5（USB-C）、J7（microSD）沒有浮腳
- [ ] C72、C73（背面 J6 那一角，22 µF 0805）沒有裂
- [ ] C30、C31、R31、R41 四個位置是空的（設計上不焊）
- [ ] U1 的焊盤上有錫、沒有連錫

## 2. 通電前量電阻（不通電，U1 還沒焊）

用電表電阻檔，黑棒接 GND（J5 的金屬外殼，或背面測試點 TP8）。

| 量哪裡 | 應該看到 | 實測 |
|---|---|---|
| J5 的 VBUS 對 GND | 不是短路（遠大於 10 Ω） | |
| 5V 對 GND（U2 第 1 或 4 腳） | 不是短路 | |
| 3V3 對 GND（J6 第 1 腳） | 不是短路 | |
| 2.5 V 對 GND（U4 第 5 腳） | 不是短路 | |
| 1.2 V 對 GND（L2 靠電容那一端） | 不是短路 | |

電容充電時讀數會慢慢爬升，這是正常的。固定在幾歐姆以下才是短路。

## 3. 第一次通電（U1 還沒焊）

這一步文件裡沒有現成的預期電流，是保守做法：先確認電源正常，再把最貴的模組焊上去。

- [ ] 有可調電源：設 5.0 V、限流 0.3 A，接 J5。沒有的話直接用 Type-C 電源
- [ ] 通電後 10 秒內用手指背面輕碰 U16、U2、U15、U4、U7，沒有發燙

| 量哪裡 | 應該看到 | 實測 |
|---|---|---|
| VBUS（J5 輸入） | 約 5.0 V | |
| 5V（eFuse 之後，U2 第 1 腳） | 約 5.0 V，和 VBUS 差不多 | |
| 3V3（J6 第 1 腳） | 3.31 V 左右（3.2–3.4 V） | |
| 2.5 V（U4 第 5 腳） | 2.5 V | |
| 1.2 V（L2 輸出端） | 1.21 V 左右（1.15–1.26 V） | |
| 電源顯示的電流 | 沒有現成數字；記下來當基準 | |

- [ ] 5V 是 0 V 而 VBUS 有電：eFuse 沒開，停下來查 U16
- [ ] 斷電，等 10 秒再做下一步

## 4. 手焊 U1

- [ ] 模組對位：第 1 腳方向和絲印一致，四邊城堡焊盤都對齊
- [ ] 先點對角兩腳固定，確認沒歪再焊其他腳
- [ ] **第 24、25 腳不要拖焊**：東側緊貼 R80、R81（0201，間距 0.387 mm）。烙鐵不要往 J6 方向帶，錫從模組那一側收，不要放多餘的錫
- [ ] **第 67–72 腳不要往板子左側拖**：R79 離第 70 腳約 1 mm
- [ ] 放大鏡檢查：R80、R81 還在、兩端沒有和 U1 焊盤連錫、沒有立碑
- [ ] 放大鏡檢查：U1 四邊沒有相鄰腳連錫
- [ ] 再量一次 3V3 對 GND 的電阻，不是短路

## 5. 接上電腦，讀晶片版本

- [ ] J5 用 USB-C 線接電腦（板子由這條線供電，電腦的埠要夠力；不夠就用有外接電源的 hub）
- [ ] 裝置管理員出現一個新的 COM 埠（USB JTAG/serial debug unit）。記下埠號：COM____
- [ ] 沒出現：把 TP1（BOOT）接到 GND，碰一下 TP2（EN）到 GND 再放開，進入下載模式

```
python -m esptool -p COM__ flash_id
```

- [ ] 輸出有 `Chip is ESP32-P4 (revision v_._)`。記下版本：v____
- [ ] 偵測到的 flash 大小是 16 MB 以上。實測：____ MB

| 晶片版本 | 要燒的映像 |
|---|---|
| v3.0 以上 | rev 3.x 映像（`build.v2r7_rev3`） |
| 低於 v3.0 | pre-3.0 映像（`build.v2r7_pre3`） |

**燒錯版本跑不起來**，一個映像只能用在一種晶片上。

## 6. 燒錄

在選定的映像資料夾裡執行（下面以 rev3 為例）：

```
cd <映像資料夾>\build.v2r7_rev3
python -m esptool --chip esp32p4 -p COM__ write_flash @flash_args
```

- [ ] 四個檔都寫完，每個都顯示 `Hash of data verified`
- [ ] 結尾是 `Hard resetting`。沒有自動重開就碰一下 TP2（EN）到 GND

寫入的位址：bootloader 0x2000、partition table 0x8000、ota data 0xf000、espkvm.bin 0x20000。

## 7. 第一次開機

**先接 UART**（背面那排測試點），開機階段的 log 只從這裡出來，J5 只有應用程式的 log：

| 測試點 | 訊號 | 接到 UART 線的 |
|---|---|---|
| TP3 | U0_TX | RX |
| TP4 | U0_RX | TX |
| TP8 | GND | GND |

115200 8N1。UART 線的 3.3 V 或 5 V 電源腳**不要接**。

- [ ] 天線線接上 J8（背面 U.FL），另一端接天線
- [ ] 重開機，UART 有 bootloader log，接著有應用程式 log，沒有一直重開
- [ ] log 裡的 PSRAM 大小：____ MB
- [ ] 手機或電腦看得到熱點 `ESP-KVM-xxxx`
- [ ] 連上熱點（密碼在 log 或 LCD 的 QR 裡），開 `http://192.168.4.1/`
- [ ] 用 admin / admin 登入，系統要求改密碼，改掉
- [ ] 再量一次 3V3、1.2 V、2.5 V，數值和第 3 步一樣
- [ ] 跑 5 分鐘，手碰 U1、U7 的溫度：燙但可以碰（沒有外殼時 U7 是最燙的）

## 8. 逐項功能

每一項獨立，哪一項失敗就記下來，繼續測下一項。

- [ ] **HDMI 擷取**：J2 接一台電腦的 HDMI 輸出，網頁看得到畫面。記下解析度：______
- [ ] **鍵盤滑鼠**：J3 用 USB-C 線接被控電腦，被控電腦認得到 HID 裝置，網頁上打字和移動滑鼠有反應
- [ ] **microSD**：插卡到 J7，網頁認得到卡和容量

## 9. 今天不要做的

- **不要接 J4（ATX）到主機板**。韌體預設關閉 ATX，開機瞬間 GPIO 4、5 的狀態沒有量過，可能誤觸電源鍵。要先用示波器照 `firmware\BUILD_v2.md` 的量測計畫量過
- **不要裝外殼做 Wi-Fi 判斷**。先在裸板記下訊號強度，裝殼後再比
- **不要在網頁上傳別的 `.bin` 或開啟線上更新**。官方映像沒有這塊板子的腳位設定，裝了會連不上
